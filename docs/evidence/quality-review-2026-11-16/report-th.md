## ข้อสรุปด้านการใช้งาน Android

**ผ่านในภาพรวม:** ตัวแอปเป็น Java/XML และใช้ส่วนควบคุม Material 3 เช่น ปุ่ม สวิตช์ แผงด้านล่าง และหน้าต่างยืนยัน มีเมนูล่างสำหรับมือถือและเมนูแนวตั้งสำหรับแท็บเล็ต

ข้อที่ยังผิดความคาดหมายคือ การจัดลำดับหน้าทำให้กด Back จากหน้าหลักแล้วกลับไปหน้าระดับหลักที่เคยเลือกไว้ ส่วนชุดสี ไอคอนเส้น และการตรึงแนวตั้งเป็นสิ่งที่โครงการกำหนดไว้ จึงไม่นับเป็นข้อผิดพลาดเพียงเพราะต่างจากค่าเริ่มต้นของระบบ

## ภาพรวมปัญหา

พบ **5 ประเด็น**: P0 = 0, P1 = 1, P2 = 4, P3 = 0

- **P0:** ปัญหาขัดขวางการใช้งานจนทำงานหลักต่อไม่ได้
- **P1:** ปัญหาสำคัญ ควรแก้ก่อนส่งรุ่นสุดท้าย
- **P2:** ปัญหาที่มีทางเลี่ยงหรือมีผลเมื่อข้อมูลเพิ่ม ควรแก้ในรอบเก็บงาน
- **P3:** รายละเอียดเล็กน้อยที่แก้เมื่อมีเวลา

ควรรักษาหน้าหลักแบบเดิมและหน้าอื่นแบบใหม่ตามที่อนุมัติ เริ่มแก้การขยายฟอนต์ของหน้าโฟกัสก่อน ตามด้วย Back ชื่อปุ่มสำหรับโปรแกรมอ่านหน้าจอ และการจัดการข้อมูล ข้อค้นพบด้านประสิทธิภาพยืนยันจากโค้ด ยังไม่ใช่ผลวัดความหน่วง อัตราเฟรม หรืออาการแอปค้างบนโทรศัพท์จริง

### 1. [P1] ตัวเลขในช่องเวลาโฟกัสถูกตัดเมื่อขยายฟอนต์ 200%

**ตำแหน่ง:** [focus_activity.xml:14](https://github.com/duckxy166/cs364-roast-app/blob/39e42ccc6af98343c0235e5cc4385ca2d691e9bf/app/src/main/res/layout/focus_activity.xml#L14) และไฟล์ชื่อเดียวกันใน `layout-sw600dp`

**หมวด:** การเข้าถึง / การปรับตามขนาดตัวอักษร

**หลักฐาน:** ทดสอบ API 36 ที่ความละเอียด 900×1600 ความหนาแน่น 400 หรือความกว้าง 360dp ภาษาอังกฤษ และ `font_scale=2.0` พบด้านบนของเลข `25` ถูกตัดในช่องกรอกที่สูงคงที่ 74dp และใช้ข้อความ 32sp ปุ่มเลือกเวลาเริ่มชิดกันและตัดบรรทัดไม่สม่ำเสมอ การตรวจเดิมที่ฟอนต์ 130% ยังผ่าน ผลครั้งนี้เป็นการขยายขอบเขตไปถึง 200%

**ผลกระทบ:** ผู้ใช้ที่ต้องการตัวอักษรใหญ่ไม่สามารถอ่านค่าที่กรอกได้ครบอย่างมั่นใจ

**แนวทางที่เกี่ยวข้อง:** ตัวอักษรต้องขยายตามระบบโดยไม่สูญเสียเนื้อหา และพื้นที่กดต้องมีขนาดอย่างน้อย 48dp

**ข้อเสนอ:** เปลี่ยนความสูงให้ขยายตามเนื้อหา เช่น `wrap_content` ร่วมกับความสูงขั้นต่ำและระยะเผื่อฟอนต์ที่พอ ปรับการเรียงปุ่มตามพื้นที่และขนาดตัวอักษร เช่น สองคอลัมน์ โดยไม่ลดฟอนต์ที่ผู้ใช้เลือก


**ภาพหลักฐาน:** [หน้าโฟกัสที่ฟอนต์ 200%](images/focus-font-200-scrolled.png) และ [ภาพก่อนเลื่อน](images/focus-font-200.png)

### 2. [P2] กด Back จากหน้าหลักแล้วกลับไปแท็บก่อนหน้า

**ตำแหน่ง:** [PutItDownNavigation.java:32](https://github.com/duckxy166/cs364-roast-app/blob/39e42ccc6af98343c0235e5cc4385ca2d691e9bf/app/src/main/java/com/cs364/roastapp/ui/PutItDownNavigation.java#L32)

**หมวด:** ความสอดคล้องกับการใช้งาน Android

**หลักฐาน:** ทำเส้นทาง หน้าหลัก → ตั้งค่า → หน้าหลัก → Back ของระบบ แล้วพบหน้าตั้งค่ากลับมาอยู่ด้านหน้า ตรวจลำดับ Activity จากระบบยืนยันแล้ว โค้ดเปิดหน้าระดับหลักด้วย `FLAG_ACTIVITY_REORDER_TO_FRONT`

**ผลกระทบ:** หน้าหลักทำหน้าที่เป็นจุดเริ่มต้นไม่สม่ำเสมอ ผู้ใช้คาดเดาผลของ Back ยากขึ้น

**แนวทางที่เกี่ยวข้อง:** พฤติกรรม Back และลำดับหน้าระดับหลักควรสอดคล้องกัน

**ข้อเสนอ:** กำหนดลำดับการย้อนกลับของหน้าระดับหลักให้ชัด โดยคงหน้าต่างยืนยันก่อนออกจากโฟกัส การใช้จุดจัดการเส้นทางกลางเป็นทางเลือกหนึ่ง แต่ไม่จำเป็นต้องรื้อระบบเพียงเพื่อเปลี่ยนรูปแบบโค้ด


**หลักฐาน:** [ลำดับ Activity หลังทดสอบ Back](evidence/back-stack.txt)

## สิ่งที่ทำได้ดีและจุดที่ตรวจแล้วไม่ถือเป็นปัญหา

- **คอนทราสต์ของคู่สีที่ตรวจผ่าน:** ธีมสว่าง ข้อความหลัก/พื้นหลัง 14.66:1 ข้อความรอง/พื้นหลัง 5.75:1 และข้อความบนพื้นรอง 7.01:1 ส่วนธีมมืดได้ 16.25:1, 9.31:1 และ 7.57:1 ตามลำดับ ข้อความสว่างบนสีน้ำเงินได้ 5.98:1 และสีหมึกบนคอรัลได้ 6.11:1 ทั้งสองธีม ตัวเลขเป็นการคำนวณจากค่าสี ไม่ใช่การยืนยันทุกพิกเซลและทุกสถานะ
- **พื้นที่กดถึงเกณฑ์ในจุดที่วัด:** บนจอ 360dp ฟอนต์ 130% ปุ่ม preset โฟกัสมีขนาด 74×48dp และแท็บล่าง 90×80dp ไม่จำเป็นต้องขยายพื้นหลังสีของแท็บให้ใหญ่เพื่อเพิ่มพื้นที่กด
- **คีย์บอร์ดไม่บังปุ่ม Save ในกรณีที่ตรวจ:** แผงตั้งเวลารายวันบนจอ 360dp ฟอนต์ 130% ย้ายขึ้นเหนือคีย์บอร์ดจริงและยังเห็นปุ่มบันทึก จึงไม่นับเป็นข้อบกพร่องในกรณีนี้
- **สวิตช์โหมดสาธิตมีชื่อและสถานะ:** ไม่ใช่สวิตช์ที่ไม่มีชื่อกำกับ
- **คำเตือน lint เรื่องภาพตกแต่งไม่ใช่ข้อผิดพลาดผู้ใช้ 4 จุด:** ไอคอนในแถวตั้งค่าถูกซ่อนจากการอ่านด้วย `noHideDescendants` และมีปุ่มทับที่ระบุชื่อแล้ว
- มีทรัพยากรธีมสว่าง/มืด ฟอนต์ Noto ในแอป รูปแบบส่วนกลาง เมนูตามขนาดจอ เนื้อหายาวเลื่อนได้ หน้าต่างยืนยัน และข้อความรายวันประกอบกราฟ
- การสร้าง debug/release และ lint ผ่านก่อน audit แล้ว รุ่น release ไม่รวมเครื่องมือเก็บภาพเฉพาะ debug รอบ audit นี้ไม่ได้สร้างแอปซ้ำจากโค้ดเดิมหรือเพิ่มส่วนพึ่งพาใหม่

## ขอบเขตและข้อจำกัดของผลตรวจ
